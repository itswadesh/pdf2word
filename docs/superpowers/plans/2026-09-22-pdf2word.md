# pdf2word Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Go CLI that converts PDF files (text or scanned) to `.docx`, using the text layer when present and Tesseract OCR otherwise.

**Architecture:** A linear pipeline — `pdftext` extracts glyphs and rebuilds paragraphs, `pdfimage` pulls embedded page images, `ocr` runs Tesseract over them, `docx` serialises the shared `model.Document`. `convert` decides per page whether to OCR; `cmd/pdf2word` only parses flags.

**Tech Stack:** Go 1.27 (no cgo), `github.com/ledongthuc/pdf`, `github.com/pdfcpu/pdfcpu v0.15.0`, `golang.org/x/image` (TIFF header decoding and fixtures), Tesseract 5 CLI at runtime.

**Spec:** `docs/superpowers/specs/2026-09-22-pdf2word-design.md`

## Global Constraints

- Go 1.27, `CGO_ENABLED=0` must build.
- Module path `pdf2word`; binary `pdf2word`.
- Only the standard library may be used by `internal/docx`.
- `go test ./...` must pass without Tesseract installed (OCR integration test skips).
- `gofmt` clean; `go vet ./...` clean.
- Commit after every task with a conventional-commit message.
